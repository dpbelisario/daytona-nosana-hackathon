Daytona and Nosana: how the parts connect

This page shows what each platform is, where your code runs, and how a request moves from the browser to the AI model.

Is Nosana a VM?No.

Nosana runs your Docker image as a container on a GPU computer that another person owns. You rent the GPU by the hour.

What is Daytona?A sandbox service.

A sandbox is an isolated Linux computer on Daytona's servers. It starts from a Docker image. It has no GPU in this setup.

Do both use Docker?Yes, Docker images.

You give each platform a Docker image. Each platform starts a container from that image. Neither gives you a full VM.

Figure 2. One question, from browser to answer

The two platforms do not talk to each other. Your page connects them.

  1. Open the page

    The browser opens the Daytona preview URL.

  2. Daytona sends the page

    The proxy finds your sandbox. The web server on port 3000 sends index.html.

  3. Send the question

    The page sends the question to the Nosana URL at /v1/chat/completions.

  4. Nosana runs the model

    The tunnel sends the request to the host. Ollama runs qwen3:8b on the GPU.

  5. Show the answer

    The answer goes back the same way. The page shows it.

Words on this page

TermMeaning
Docker imageA packed set of files: an operating system base, the app, and its libraries. It does not run by itself.
ContainerA running copy of an image. It shares the server's Linux kernel but cannot see other containers.
VMVirtual machine. A full computer in software, with its own operating system.
Sandbox DDaytona's isolated Linux environment. You create, start, stop and delete it with the SDK or dashboard.
Snapshot DThe Docker image that a sandbox starts from.
Runner DA Daytona server that holds many sandboxes.
Preview URL DA public link to one port in a sandbox: https://<port>-<sandbox-id>.<proxy>.
Volume DA shared folder that stays after sandboxes are deleted.
Host / node NA GPU computer that another person owns. It runs Nosana software and earns NOS tokens for jobs.
Job NOne run of your container on one host, for a fixed time.
Job definition NThe JSON that tells the host which image to run, which command, which port to open, and whether to use the GPU.
Deployment NA manager for jobs. It restarts and replaces jobs so your service stays up.
Market NA queue for one GPU type, with one price per hour.
Endpoint NThe public URL of your job's open port.
GPU / VRAMThe graphics chip that runs AI models fast, and its memory. The model must fit in VRAM.
PortA numbered door on a computer. A web server listens on one port, for example 3000 or 11434.
OllamaSoftware that downloads and serves open AI models. It has an OpenAI-compatible API.
API keyA secret password for scripts. Keep it in .env. Do not put it in Git or in a web page.

Procedure: complete the setup

  1. Wait until the Nosana deployment shows a new event after "Job list confirmed".
  2. Run curl <ENDPOINT>/v1/models. Continue when the result is JSON, not an HTML page.
  3. Get a Daytona API key at app.daytona.io → API Keys. Put it in .env.
  4. Run npm run daytona:web. Open the URL that it shows.
  5. Put the Nosana endpoint in the first box of the page. Send a question.

CAUTION: Both platforms use credits while your work runs. Stop the Nosana deployment (Actions → Stop) and run npm run daytona:clean when you finish.
